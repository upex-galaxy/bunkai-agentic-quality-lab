# ATC Spec: BK-1376 - The `expand` parser applies its documented rules

> Ticket: BK-1376 (BK-595 TC09, AC-02 / 2.5, Level: API)
> Component: `AtcsApi` (existing, extended in this Work Package)
> Type: API - Boundary (query parser)
> Parent Story: BK-595 (`TMS-ATC API | Read a single ATC by id`)

## 1. Test Case Summary

| Name | Objective | Precondition | Acceptance Criteria |
|------|-----------|--------------|---------------------|
| `expectExpandParserApplied` | The `expand` query is parsed with the documented rules - case-insensitive, trimmed, empty segments ignored, duplicates collapsed, repeated params merged - and the resulting set drives which collections the payload carries | An accessible ATC in the caller's workspace and a credential holding `atc:read` | AC-02 / 2.5: the parser rules shipped in `lib/atcs/expand.ts` are observable through the response, and any unrecognised token is still refused (BK-1377 owns the refusal) |

## 2. ATC Contract

```typescript
/**
 * ATC: The `expand` query is normalised before use (case, whitespace, empty
 * segments, duplicates, repeated params) and the payload carries exactly the
 * requested collections.
 *
 * Fixed assertions:
 *  - status 200
 *  - top-level body keys are exactly ['atc']
 *  - for each of steps / assertions / acceptance_criteria / used_in, presence
 *    equals membership in `expected`
 *  - `acceptance_criterion_ids` never appears (the handler strips it)
 */
@atc('BK-1376')
async expectExpandParserApplied(
  args: { atcId: string, query: string, expected: AtcExpansionKey[] },
): Promise<[APIResponse, AtcGetResponse]>
```

One object parameter; the credential is whatever the fixture set on the component. The raw query string is passed verbatim because Playwright's `params` map cannot express a repeated key.

## 4. Assertions Split

### Fixed (inside ATC)

- `expect(response.status()).toBe(200)`
- `expect(Object.keys(body)).toEqual(['atc'])`
- loop over `EXPANSION_KEYS` asserting `key in body.atc === expected.includes(key)`
- `expect('acceptance_criterion_ids' in body.atc).toBe(false)`

### Test-level (in test file)

- Which query string each row sends and which collections it expects. One Playwright `test()` per row so a failure names the rule that broke.

## 5. Code Template

```typescript
@atc('BK-1376')
async expectExpandParserApplied(
  args: { atcId: string, query: string, expected: AtcExpansionKey[] },
): Promise<[APIResponse, AtcGetResponse]> {
  const [response, body] = await this.apiGET<AtcGetResponse>(`/v1/atcs/${args.atcId}${args.query}`);

  expect(response.status()).toBe(200);
  expect(Object.keys(body)).toEqual(['atc']);

  for (const key of EXPANSION_KEYS) {
    expect(key in body.atc, `'${key}' presence must follow the expected set`).toBe(
      args.expected.includes(key),
    );
  }
  expect('acceptance_criterion_ids' in body.atc).toBe(false);

  return [response, body];
}
```

Test file (`tests/integration/atcs/parseAtcExpandQuery.test.ts`, fixture `{ api }`):

| Row | Query | Expected present |
|-----|-------|------------------|
| uppercase | `?expand=STEPS` | `steps` |
| padded | `?expand=%20steps%20,%20assertions%20` | `steps`, `assertions` |
| duplicates | `?expand=steps,steps` | `steps` |
| empty | `?expand=` | none |
| repeated param | `?expand=steps&expand=assertions` | `steps`, `assertions` |
