# ATC Spec: BK-1386 - A write-only token is refused with 403 and no data

> Ticket: BK-1386 (BK-595 TC19, AC-05 / 5.2, Level: API)
> Component: `AtcsApi` (existing, extended in this Work Package)
> Type: API - Negative (capability posture)
> Parent Story: BK-595 (`TMS-ATC API | Read a single ATC by id`)

## 1. Test Case Summary

| Name | Objective | Precondition | Acceptance Criteria |
|------|-----------|--------------|---------------------|
| `expectReadRefusedForMissingCapability` | A caller authenticated with a PAT that carries only `atc:write` cannot read the ATC: 403 `forbidden`, the message names the missing capability, and the body carries no ATC data | A PAT minted with `pat_scopes: ['atc:write']` for the workspace member, an accessible ATC id | AC-05 / 5.2: 403, `error.code = 'forbidden'`, message names `atc:read`, top-level keys exactly `['error']` |

## 2. ATC Contract

```typescript
/**
 * ATC: Reading an ATC with a credential that lacks `atc:read` answers 403
 * `forbidden` naming the missing capability, and the refusal carries only the
 * error envelope.
 *
 * Fixed assertions:
 *  - status 403
 *  - top-level body keys are exactly ['error'] (no `atc`, no title, no version)
 *  - body.error.code is 'forbidden'
 *  - body.error.message contains 'atc:read'
 */
@atc('BK-1386')
async expectReadRefusedForMissingCapability(atcId: string): Promise<[APIResponse, ErrorEnvelope]>
```

One positional parameter. The credential is not a parameter: it is whatever the test set on the component via `api.setAuthToken(pat.token)`, the same convention as `OpenBugsApi.expectAccessDecision` and `TraceabilityApi.expectUnauthenticatedRejection`.

## 3A. API Details

| Aspect | Value |
|--------|-------|
| Endpoint | `GET /api/v1/atcs/{id}` |
| Types | `ErrorEnvelope` (`@schemas/auth.types`), `APIResponse` |
| Capability | `{ auth: 'required', requires: ['atc:read'] }` on the route |
| Refusal source | `lib/api/principal.ts` — `throw new ApiError('forbidden', 'Missing required capability: atc:read')` |
| Check order | The wrapper resolves credential + capability BEFORE the handler validates the id or parses `expand`, so the ATC id passed here is never inspected |
| PAT minting | `AuthApi.mintScopedPat({ scopes: ['atc:write'] })` — signin's `pat_scopes` enum accepts `atc:write`; the returned `revoke()` is called in a `finally` |
| Source of truth | `app/api/v1/atcs/[id]/route.ts`, `lib/api/handler.ts`, `lib/api/principal.ts` (backend repo, read-only) |

## 4. Assertions Split

### Fixed (inside ATC)

- `expect(response.status()).toBe(403)`
- `expect(Object.keys(body)).toEqual(['error'])`
- `expect(body.error.code).toBe('forbidden')`
- `expect(body.error.message).toContain('atc:read')`

### Test-level (in test file)

- Minting the write-only PAT, setting it on the component, and revoking it in `finally`. The seed ATC id the row reads.

## 5. Code Template

```typescript
@atc('BK-1386')
async expectReadRefusedForMissingCapability(atcId: string): Promise<[APIResponse, ErrorEnvelope]> {
  const [response, body] = await this.apiGET<ErrorEnvelope>(`/v1/atcs/${atcId}`);

  expect(response.status()).toBe(403);
  expect(Object.keys(body)).toEqual(['error']);
  expect(body.error.code).toBe('forbidden');
  expect(body.error.message).toContain('atc:read');

  return [response, body];
}
```

Test file (`tests/integration/atcs/rejectAtcReadAccess.test.ts`, fixture `{ api }`):

```typescript
const pat = await api.auth.mintScopedPat({ scopes: ['atc:write'] });
try {
  api.setAuthToken(pat.token);
  await api.atcs.expectReadRefusedForMissingCapability(FIXTURE_ATC_ID);
}
finally {
  await pat.revoke();
}
```
