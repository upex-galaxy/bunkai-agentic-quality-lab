# ATC Spec: BK-1379 - A malformed ATC id is a bad request, not a lookup

> Ticket: BK-1379 (BK-595 TC12, P0, AC-03 / 3.2, ROI 7.50)
> Component: AtcsApi (`tests/components/api/AuthApi.ts` untouched; `AtcsApi` new in this Work Package)
> Type: API - Negative (path validation)
> Parent Story: BK-595 (`TMS-ATC API | Read a single ATC by id`)

## 1. Test Case Summary

| Name | Objective | Precondition | Acceptance Criteria |
|------|-----------|--------------|---------------------|
| `expectMalformedAtcIdRejected` | A path segment that fails the route's UUID regex answers 400 `bad_request` with the documented message and only the error envelope, and no lookup is attempted | Credential holding `atc:read` (the wrapper authenticates before the id is validated); no fixture data | AC-03 / 3.2: 400, `error.code = 'bad_request'`, message matches `/atc id must be a uuid/i`, top-level keys exactly `['error']` |

## 2. ATC Contract

```typescript
/**
 * ATC: Reading an ATC whose path segment fails the route's UUID regex returns
 * 400 `bad_request`, and the refusal carries only the error envelope.
 *
 * Fixed assertions:
 *  - status 400
 *  - top-level body keys are exactly ['error']
 *  - body.error.code is 'bad_request'
 *  - body.error.message matches /atc id must be a uuid/i
 */
@atc('BK-1379')
async expectMalformedAtcIdRejected(malformedAtcId: string): Promise<[APIResponse, ErrorEnvelope]>
```

One positional parameter; the same ATC serves every row of the EP/BVA table.

## 3A. API Details

| Aspect | Value |
|--------|-------|
| Endpoint | `GET /api/v1/atcs/{id}` |
| Types | `ErrorEnvelope` (`@schemas/auth.types`), `APIResponse` (`@playwright/test`) |
| Auth | Bearer `atc:read` — the wrapper resolves it before the handler runs, so a malformed id from an anonymous caller is 401, never 400 (precedence owned by TC15 / BK-1382, deferred) |
| Id extraction | `extractAtcId` takes the last non-empty path segment |
| Route regex | `/^[\da-f]{8}-[\da-f]{4}-[\da-f]{4}-[\da-f]{4}-[\da-f]{12}$/i` — case-insensitive, so an uppercase canonical UUID is VALID |
| Error | `ApiError('bad_request', 'ATC id must be a UUID.')` with no `details`, mapped to HTTP 400 |
| Lookup | None: the throw happens before `getAtc`, so no RPC call and no database read |
| Source of truth | `app/api/v1/atcs/[id]/route.ts` (`extractAtcId`, `isUuid`; backend repo, read-only) |

## 4. Assertions Split

### Fixed (inside ATC)

- `expect(response.status()).toBe(400)`
- `expect(Object.keys(body)).toEqual(['error'])` — non-disclosure: no `atc` key
- `expect(body.error.code).toBe('bad_request')`
- `expect(body.error.message).toMatch(/atc id must be a uuid/i)`

### Test-level (in test file)

- Which malformed id each row feeds (the EP/BVA table). One Playwright `test()` per row so a failure names the shape that broke, and each row gets its own `api` context.

## 5. Code Template

```typescript
@atc('BK-1379')
async expectMalformedAtcIdRejected(malformedAtcId: string): Promise<[APIResponse, ErrorEnvelope]> {
  const [response, body] = await this.apiGET<ErrorEnvelope>(`/v1/atcs/${malformedAtcId}`);

  expect(response.status()).toBe(400);
  expect(Object.keys(body)).toEqual(['error']);
  expect(body.error.code).toBe('bad_request');
  expect(body.error.message).toMatch(/atc id must be a uuid/i);

  return [response, body];
}
```

Test file (`tests/integration/atcs/rejectInvalidAtcRead.test.ts`, fixture `{ api }`):

```typescript
const MALFORMED_ROWS: ReadonlyArray<MalformedIdRow> = [

    await api.atcs.expectMalformedAtcIdRejected(row.id);
  });
}
```

## 6. Technique-derivation check

| AC | Technique fired | ATCs produced |
|----|-----------------|---------------|
| AC-03 / 3.2 (malformed id is 400) | EP on the id format (canonical UUID vs invalid formats) + BVA on the 36-character length | 1 parameterized ATC, 4 rows |

**Equivalence Partitioning detail:**

| Input | Expected output | Same ATC? |
|-------|-----------------|-----------|
| Canonical UUID, 36 characters | 200 | Not repeated: BK-1368 owns it; listed only to delimit the partition |
| Plain word `not-a-uuid` | 400, envelope only | Yes — row 1 |
| Dashless 32-hex string | 400, envelope only | Yes — row 2 (missing 8-4-4-4-12 grouping, not a character-class failure) |
| Id 35 characters long | 400 | Yes — row 3 (boundary) |
| Id 37 characters long | 400 | Yes — row 4 (boundary) |
| Whitespace-padded UUID / SQL-like string (listed in the Jira TC) | 400 | Same partition. Not rows here: Next.js normalises the path segment, so the padded form no longer reaches the regex as typed, and a SQL-like string is one more instance of the plain-word partition |

**Boundary Value Analysis detail** (the id must be exactly 36 characters in the canonical grouping):

| Field + range | Boundary rows |
|---------------|---------------|
| Path id length, valid = 36 (fixed) | 35 → 400 (row 3); 36 → 200 (BK-1368, not repeated); 37 → 400 (row 4) |

The 35- and 37-character ids are the seed UUID with its last character removed and with one character appended, so only the length boundary changes.

**BVA-D**: N/A — nothing is rounded or truncated; the id is accepted or rejected whole.

**Reduction axes:**

| Parameterized ATC | Reduction applied | Rows after reduction |
|-------------------|-------------------|----------------------|
| `expectMalformedAtcIdRejected` | none: one factor (the id string) | 4 |
