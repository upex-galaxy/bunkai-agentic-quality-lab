# ATC Spec: BK-1387 - An unauthenticated read is refused with 401

> Ticket: BK-1387 (BK-595 TC20, AC-05 / 5.3, Level: API)
> Component: `AtcsApi` (existing, extended in this Work Package)
> Type: API - Negative (authentication posture)
> Parent Story: BK-595 (`TMS-ATC API | Read a single ATC by id`)

## 1. Test Case Summary

| Name | Objective | Precondition | Acceptance Criteria |
|------|-----------|--------------|---------------------|
| `expectReadRefusedForAnonymousCaller` | A request with no credential at all is refused with 401 `unauthorized` before any lookup, and the refusal carries only the error envelope | A bare request context: no Bearer header, no session cookie (`api.clearAuthToken()` on the integration project, whose `use: {}` carries no storageState) | AC-05 / 5.3: 401, `error.code = 'unauthorized'`, top-level keys exactly `['error']`, no ATC data |

## 2. ATC Contract

```typescript
/**
 * ATC: Reading an ATC with no credential answers 401 `unauthorized` and the
 * refusal carries only the error envelope.
 *
 * Fixed assertions:
 *  - status 401
 *  - top-level body keys are exactly ['error']
 *  - body.error.code is 'unauthorized'
 *  - body.error.message is non-empty
 */
@atc('BK-1387')
async expectReadRefusedForAnonymousCaller(atcId: string): Promise<[APIResponse, ErrorEnvelope]>
```

One positional parameter. The credential is not a parameter: the test clears it on the component (`api.clearAuthToken()`) because the integration project loads the login PAT from `.auth/api-state.json` by default.

## 3A. API Details

| Aspect | Value |
|--------|-------|
| Endpoint | `GET /api/v1/atcs/{id}` |
| Types | `ErrorEnvelope` (`@schemas/auth.types`), `APIResponse` |
| Route posture | `{ auth: 'required', requires: ['atc:read'] }` |
| Refusal source | `lib/api/principal.ts` — `throw new ApiError('unauthorized', 'Authentication required.')` when no principal resolves |
| Check order | Authentication runs in the wrapper BEFORE id validation and `expand` parsing, so the ATC id passed here is never inspected (precedence between 401 and 400 is owned by BK-1382, not automated in this pass) |
| Cookie caveat | The `integration` project runs with `use: {}` (no `storageState`), so clearing the token genuinely produces an anonymous request; a browser-session project would need a fresh `request.newContext()` instead |
| Source of truth | `app/api/v1/atcs/[id]/route.ts`, `lib/api/handler.ts`, `lib/api/principal.ts` (backend repo, read-only) |

## 4. Assertions Split

### Fixed (inside ATC)

- `expect(response.status()).toBe(401)`
- `expect(Object.keys(body)).toEqual(['error'])`
- `expect(body.error.code).toBe('unauthorized')`
- `expect(typeof body.error.message).toBe('string')` and non-empty

The exact wording is asserted only for code, not message text: `Authentication required.` is the shipped string but the AC fixes the status and non-disclosure, not the copy.

### Test-level (in test file)

- Clearing the credential before the call and restoring it after (`finally`), so a later test in the same worker does not inherit an anonymous component.

## 5. Code Template

```typescript
@atc('BK-1387')
async expectReadRefusedForAnonymousCaller(atcId: string): Promise<[APIResponse, ErrorEnvelope]> {
  const [response, body] = await this.apiGET<ErrorEnvelope>(`/v1/atcs/${atcId}`);

  expect(response.status()).toBe(401);
  expect(Object.keys(body)).toEqual(['error']);
  expect(body.error.code).toBe('unauthorized');
  expect(body.error.message.length).toBeGreaterThan(0);

  return [response, body];
}
```

Test file (`tests/integration/atcs/rejectAtcReadAccess.test.ts`, fixture `{ api }`):

```typescript

finally {

}
```
