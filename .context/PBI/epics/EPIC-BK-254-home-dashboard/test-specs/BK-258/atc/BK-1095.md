# ATC Spec: BK-1095 - Home excludes open bugs whose module is archived

> Ticket: BK-1095 (BK-258 TC3, High, ROI 0.8, prior-bug rule c9cd8af9). Pass 3. Gate verdict: AUTOMATE (closes the manual-only AC1.b gap)
> Component: HomePage (`tests/components/ui/HomePage.ts`, existing from pass 1)
> Type: UI verification with API oracle at test level, EP (module active vs archived) + State-Transition (module archive)
> Parent Story: BK-258 (AC1.b refined archived-module rule)

## 1. Test Case Summary

| Name | Objective | Precondition | Acceptance Criteria |
|------|-----------|--------------|---------------------|
| `showsOpenBugCountsExcludingArchivedModule` | After the module holding 2 open P1 bugs is archived, the Home card shows the still-active module's P2 bug only: total and P1 drop by 2, P2 is unchanged | Owner signed in (cookie identity); baseline read from the API; one active module with 1 open P2 bug; a second module with 2 open P1 bugs; the pre-archive count proven through the API | AC1.b: total decreases by 2; P1 Critical decreases by 2; P2 Major unchanged; the open-bugs API returns the same `open_count` and `by_severity` as the card |

**ATC placement.** The ATC lives on `HomePage`: the card is the subject of the TC and the rendered count is the business outcome. `OpenBugsApi` gets no new method. `getOpenBugs` is already the `@step` helper and serves as the oracle; a second `OpenBugsApi` ATC asserting the same numbers would be a disguised helper (no Jira Test of its own) and would drop the card-vs-server render risk, because the card counts through the server-side `countOpenBugs`, not through the REST route. `ProjectsApi.archiveModuleSuccessfully` stays a helper: it is the state-change action, not the outcome this TC measures.

 * unscoped count test id resolved to a second element outside the card.

@atc('BK-1095')

## 4. Assertions Split

- Fixed (ATC): skeleton gone, total, P1 chip, P2 chip.
- Test level, before the action: `baseline = getOpenBugs(workspaceId)` before seeding; after seeding, `before = getOpenBugs(workspaceId)` must equal `baseline.open_count + 3`, `baseline.by_severity.P1 + 2`, `baseline.by_severity.P2 + 1`. This is the TC's "counts before archiving noted" precondition and the proof that the -2 cannot pass vacuously.
- Test level, after the ATC: `getOpenBugs(workspaceId)` must equal `expected.total`, `expected.P1`, `expected.P2` (API agrees with the card).
- Test level, cleanup: archive both modules, re-read the count and warn (never assert) if the baseline was not restored.

Deviation from the TC wording: the TC says the pre-archive counts are read from Home. The automation reads them from the API, the oracle the TC itself declares, and reads the card once, after the archive. An ATC is an assertion, not a reader; a second Home read would need a page helper for no extra signal, and calling another ticket's ATC (BK-1093) from this test is forbidden. The delta semantics of the expected results are unchanged.

## 5. Code Template

ATC implementation (added to `HomePage`, reuses `waitForCardSettled` and `SEVERITY_LABELS`):

```typescript
@atc('BK-1095')
async showsOpenBugCountsExcludingArchivedModule(expected: { total: number, P1: number, P2: number }): Promise<void> {
  await this.waitForCardSettled();

  const card = this.page.getByRole('region', { name: 'Open bugs' });
  await expect(card.getByTestId('home-open-bugs-count')).toHaveText(String(expected.total));

  const p1Chip = card.getByTestId('home-open-bugs-severity-P1');
  await expect(p1Chip).toBeVisible();
  await expect(p1Chip).toHaveText(new RegExp(`^P1\\s*${SEVERITY_LABELS.P1}\\s*${expected.P1}$`));

  const p2Chip = card.getByTestId('home-open-bugs-severity-P2');
  await expect(p2Chip).toBeVisible();
  await expect(p2Chip).toHaveText(new RegExp(`^P2\\s*${SEVERITY_LABELS.P2}\\s*${expected.P2}$`));
}
```

Test flow (`tests/e2e/home/viewOpenBugsArchiveExclusion.test.ts`, fixture `{ test }`):

```typescript
import type { ApiFixture } from '@ApiFixture';

import { expect, test } from '@TestFixture';

async function archiveQuietly(api: ApiFixture, moduleId: string | undefined, label: string): Promise<void> {
  if (!moduleId) {
    return;
  }
  try {
    await api.projects.archiveModuleSuccessfully(moduleId);
  }
  catch (error) {
    console.warn(`[BK-1095] cleanup failed, archive ${label} module ${moduleId} manually: ${error instanceof Error ? error.message : String(error)}`);
  }
}

test.describe('BK-258: Home open bugs card archived-module exclusion', { tag: ['@regression'] }, () => {
  test('BK-1095: should exclude open bugs from the count when their module is archived', async ({ test: fixture }) => {
    const { api, ui } = fixture;
    fixture.clearAuthToken();

    const [, me] = await api.auth.getCurrentUser();
    const workspaceId = me.active_workspace_id;
    expect(workspaceId).toBeTruthy();

    const [, baseline] = await api.openBugs.getOpenBugs(workspaceId!);

    // Projects cannot be deleted and the existing QA project is ranked out of
    // `recent-projects` (max 20), so create one per run; no project-list endpoint.
    const [, project] = await api.projects.createProjectSuccessfully(
      workspaceId!,
      api.data.createProject({ name: `BK-258 QA archive ${api.data.createTestId('exclusion')}` }),
    );
    const projectId = project.project.id;

    let activeModuleId: string | undefined;
    let archivedModuleId: string | undefined;
    let archiveCompleted = false;

    try {
      const [, activeModule] = await api.projects.createModuleSuccessfully({
        projectId,
        payload: api.data.createModule(),
      });
      activeModuleId = activeModule.module.id;

      const [, archivedModule] = await api.projects.createModuleSuccessfully({
        projectId,
        payload: api.data.createModule(),
      });
      archivedModuleId = archivedModule.module.id;

      // Active-module control: 1 open P2 bug. Archived module: 2 open P1 bugs.
      await api.bugs.createBugSuccessfully({
        project_id: projectId,
        module_id: activeModule.module.id,
        ...api.data.createBug({ severity: 'P2' }),
      });
      for (let i = 0; i < 2; i++) {
        await api.bugs.createBugSuccessfully({
          project_id: projectId,
          module_id: archivedModule.module.id,
          ...api.data.createBug({ severity: 'P1' }),
        });
      }

      // The TC's "counts before archiving noted": prove the 3 seeded bugs were counted.
      const [, before] = await api.openBugs.getOpenBugs(workspaceId!);
      expect(before.open_count).toBe(baseline.open_count + 3);
      expect(before.by_severity.P1).toBe(baseline.by_severity.P1 + 2);
      expect(before.by_severity.P2).toBe(baseline.by_severity.P2 + 1);

      // ACTION: archive the module that holds the two P1 bugs.
      await api.projects.archiveModuleSuccessfully(archivedModule.module.id);
      archiveCompleted = true;

      const expected = {
        total: before.open_count - 2,
        P1: before.by_severity.P1 - 2,
        P2: before.by_severity.P2,
      };

      await ui.home.open();
      await ui.home.showsOpenBugCountsExcludingArchivedModule(expected);

      // The card matched `expected`; the server must agree.
      const [, after] = await api.openBugs.getOpenBugs(workspaceId!);
      expect(after.open_count).toBe(expected.total);
      expect(after.by_severity.P1).toBe(expected.P1);
      expect(after.by_severity.P2).toBe(expected.P2);
    }
    finally {
      // Cleanup must never replace the in-flight failure: warn and move on.
      await archiveQuietly(api, activeModuleId, 'active');
      if (!archiveCompleted) {
        await archiveQuietly(api, archivedModuleId, 'archived');
      }

      try {
        const [, afterCleanup] = await api.openBugs.getOpenBugs(workspaceId!);
        if (afterCleanup.open_count !== baseline.open_count) {
          console.warn(`[BK-1095] workspace did not return to its baseline: before=${baseline.open_count} after=${afterCleanup.open_count}`);
        }
      }
      catch (error) {
        console.warn(`[BK-1095] cleanup baseline re-read failed: ${error instanceof Error ? error.message : String(error)}`);
      }
    }
  });
});
```

## 8. Data Context

| Precondition | Pattern | Source | Cleanup |
|--------------|---------|--------|---------|
| Baseline (total, P1, P2) | Discover | `getOpenBugs(workspaceId)` before seeding | none |
| Signed-in owner + workspace id | Discover | `clearAuthToken()` + `AuthApi.getCurrentUser().active_workspace_id` | none |

| Active module + 1 open P2 bug | Generate | `createModuleSuccessfully` + `createBugSuccessfully({ severity: 'P2' })` | module archived in `finally` (its still-open bug then drops out of the count) |
| Archived module + 2 open P1 bugs | Generate + Modify | `createModuleSuccessfully` + 2x `createBugSuccessfully({ severity: 'P1' })`; `archiveModuleSuccessfully` is the ACTION | already archived by the action; `finally` archives it only if the action did not complete |
| Browser active workspace | Discover (server side) | the user's `active_workspace_id`; the test never switches workspace | none |

**Cleanup dependency resolution (the pass-2 open question).** Pass 2 recorded that BK-1094's cleanup restores the baseline only through the archived-module exclusion, and that the rule's only verification was this TC, still manual. Automating BK-1095 changes that in three ways. First, AC1.b gains an automated assertion: a regression of c9cd8af9 fails BK-1095 instead of surviving unseen. Second, it does NOT make BK-1094's cleanup self-verifying: that cleanup still only logs a console warning when the baseline is not restored, and BK-1094 would not fail for a rule BK-1095 owns. Third, if the exclusion regresses, BK-1095 fails on its core assertion before cleanup, and its cleanup warning names the unrestored baseline, so the residue is reported by a red test plus a warning instead of by nothing. The manual-only coverage gap for AC1.b is closed; BK-1094's console-only baseline check remains by design.
